Phishing Kit Reuse:
One Kit, 47 Domains

A single SOC alert on a spoofed login portal led to the discovery of 47 active phishing domains deployed from the same kit, linked to a threat actor running at least three distinct credential-harvesting campaigns.

Anonymized and sanitized for public disclosure. IOCs, client names, and identifying infrastructure details have been modified.

01 Initial Signal

The investigation started with a threat feed alert: a URL flagged by a partner feed as a spoofed login page mimicking a regional bank's online portal. The URL had been live for less than 4 hours — consistent with fast-flux hosting designed to stay ahead of blocklist propagation.

Initial triage confirmed the page was a credential harvesting kit — a near-pixel-perfect clone of the bank's login page, with one distinguishing marker: a non-standard cookie name set on page load before the form was rendered.

HTTP response headers (sanitized) HTTP/1.1 200 OK Server: Apache/2.4.51 Set-Cookie: _ssid_tok=a3f9c2; Path=/; HttpOnly Content-Type: text/html; charset=UTF-8 X-Powered-By: PHP/7.4.28 click to copy

Finding

The cookie name _ssid_tok and PHP/7.4.28 fingerprint did not match anything in the legitimate bank's infrastructure. This combination became the first kit fingerprint element.

02 Kit Fingerprinting

Pulling the kit source via CyberChef (base64 decode + URL decode chain) revealed a PHP redirect script pattern. The harvested credentials were exfiltrated via a Telegram bot API call embedded in the PHP backend — a common but specific indicator.

Three fingerprint elements were extracted from the kit that proved unique enough to search across passive DNS and URLScan historical data:

Kit fingerprint markers 1. Cookie: _ssid_tok (set before form render) 2. Telegram exfil endpoint: api.telegram[.]org/bot<TOKEN>/sendMessage 3. HTML comment in source: <!-- v2.4-ENT --> 4. CSS class collision: .lgin-frm (typo, preserved across all kit variants) 5. User-agent gate: PHP script checks for "bot" UA and returns 404 click to copy

The .lgin-frm typo was the most reliable indicator — it appeared in the kit's stylesheet and was consistent across all variants, suggesting the actor never modified the base template CSS.

Key Indicator

CSS class .lgin-frm (typo for .login-form) present in all 47 identified domains. Searchable via URLScan content search and passive HTML scraping.

03 Infrastructure Pivot

Using the kit fingerprints and the original hosting IP (192.0.2.47), infrastructure pivoting across URLScan, WHOIS, and passive DNS returned a cluster of domains sharing:

  • Same registrar (NameCheap), all registered within a 9-day window
  • Identical NS records pointing to a bulletproof hosting AS
  • SSL certificates from the same ACME provider, issued within 48 hours of domain registration
  • Matching Referrer-Policy: no-referrer header — unusual for a legitimate login page
WHOIS pattern (representative) Domain: secure-banklogin-verify[.]com Registrar: NameCheap, Inc. Created: 2025-01-14T03:22:00Z Name Server: ns1.hostingcluster-anon[.]net Name Server: ns2.hostingcluster-anon[.]net Registrant: REDACTED FOR PRIVACY click to copy

The 9-day registration burst — 47 domains across 3 distinct domain themes (bank, payment processor, parcel delivery) — indicated pre-staging ahead of a multi-target campaign launch.

Critical Finding

47 domains identified across 3 campaign themes. All pre-staged within the same registration window. 31 were not yet live at time of discovery — catch before deployment.

04 Campaign Attribution

Cross-referencing the Telegram bot token against prior IOC databases surfaced a match: the same token had been observed in a credential harvesting campaign targeting a European telecom in Q4 2024. That campaign had been attributed to a financially-motivated actor cluster operating out of Eastern Europe.

The kit version tag v2.4-ENT was consistent with a known phishing-as-a-service (PhaaS) kit sold in closed Telegram channels. This suggested the actor was either a kit customer or a reseller operating multiple simultaneous campaigns for different buyers.

T1566.002 — Spearphishing Link T1078 — Valid Accounts T1056.003 — Web Portal Capture T1583.001 — Acquire Domain T1071.001 — Web Protocols (C2 via Telegram)

The PhaaS attribution changed the response posture: rather than a one-off takedown, the recommendation was to treat this as ongoing infrastructure and monitor the registrar pattern for new domain batches.

05 Outcome

All 47 domains were submitted to the relevant registrar abuse team and the hosting provider. 43 were suspended within 72 hours. The 4 remaining domains had already propagated to a secondary hosting cluster but were subsequently actioned within a week.

The Telegram bot token was reported to Telegram's abuse team and the bot was disabled. The complete IOC set — domains, IPs, SSL certificate fingerprints, kit hash, and Telegram token — was packaged and shared with the client's security team and two ISACs.

Lessons learned: The bot exfil endpoint was the highest-confidence pivot point and could have been identified 30 minutes into the investigation. Adding Telegram bot token extraction to the standard phishing kit triage runbook was recommended and implemented.

Summary

47 domains identified → 43 suspended in 72 hrs. IOCs shared with 2 ISACs. Runbook updated with Telegram bot token extraction step. Pre-staged domains caught before deployment reduced victim exposure.
