6 Hours from Initial Access
to Domain Admin

Automated alerting produced a single low-priority SSH brute-force alert. Manual log correlation revealed that the attacker had already pivoted from that initial access to three internal hosts and achieved domain admin privileges — all within a six-hour window the SIEM had not flagged.

01 Anomaly Detection

During routine log review, a pattern caught attention that the SIEM had deprioritized: a low-score SSH brute-force alert on an internet-facing jump server, followed 22 minutes later by a successful authentication from the same external IP. The success event had not triggered an alert because the SIEM rule required 50+ failed attempts before escalating — this attacker had used a slow-spray approach with only 8 attempts over 18 minutes.

The jump server was expected to receive external SSH connections. That, combined with the below-threshold attempt count, meant automated detection missed the pivot entirely.

Critical Gap

SIEM threshold of 50 failed attempts before alerting allowed slow-spray brute-force (8 attempts, 18 min spread) to succeed without triggering detection. Success event (4624) was not correlated with preceding failures.

02 Timeline Reconstruction

Once the initial access was confirmed, the investigation pivoted to trace all subsequent activity from the compromised account j.harris. Pulling authentication events, process creation logs, and network connection logs from the SIEM reconstructed the full 6-hour chain:

Reconstructed attack timeline 02:29 [INITIAL ACCESS] SSH login as j.harris from 192.0.2.88 → jump-srv-01 02:34 [DISCOVERY] net user /domain (EventID 4661 — SAM query) 02:38 [DISCOVERY] net group "Domain Admins" /domain 02:51 [CREDENTIAL] sekurlsa::logonpasswords equivalent — LSASS memory read (EventID 10 — Process access on lsass.exe) 03:14 [LATERAL MOVE] Pass-the-hash to internal-srv-04 as svc_deploy (EventID 4624, LogonType 3, NTLM auth) 03:29 [LATERAL MOVE] RDP to dc-backup-01 as svc_deploy (EventID 4624, LogonType 10) 04:02 [PRIV ESC] Add j.harris to Domain Admins group (EventID 4728) 04:11 [PERSISTENCE] New scheduled task created: "WindowsUpdateHelper" (EventID 4698) 08:27 [DISCOVERY] Detected during routine log review click to copy

The 4-hour gap between domain admin acquisition (04:02) and detection (08:27) meant the attacker had undetected persistence for over 4 hours. The scheduled task WindowsUpdateHelper was confirmed malicious — it executed a PowerShell encoded command that beaconed to an external C2 every 15 minutes.

03 Privilege Escalation Path

The escalation path relied entirely on credential material harvested from LSASS memory on the jump server — a technique that succeeds when credential caching is enabled and LSASS isn't protected by Credential Guard.

The service account svc_deploy whose NTLM hash was stolen had elevated privileges across multiple systems due to legacy deployment requirements. This is the exact blast-radius failure mode that least-privilege architecture is designed to prevent.

EventID 4728 — Group membership change EventID: 4728 Description: A member was added to a security-enabled global group Subject: svc_deploy (elevated via pass-the-hash) Member: j.harris Group: Domain Admins DC: dc-backup-01 Time: 2025-09-03 04:02:17 click to copy

Root Cause

svc_deploy had excessive privileges across 14 internal systems with no MFA requirement and credentials cached in LSASS on the jump server. Single stolen hash = full lateral movement chain.

04 ATT&CK Mapping

The full attack chain mapped cleanly to MITRE ATT&CK techniques. The attacker's methodology was not novel — it followed a well-documented playbook for internal network compromise using stolen credentials. What made it effective was the combination of slow-spray delivery below alert thresholds and a privileged service account with no MFA.

T1110.003 — Password Spraying T1078 — Valid Accounts T1003.001 — LSASS Memory Dump T1550.002 — Pass the Hash T1021.001 — Remote Desktop Protocol T1078.002 — Domain Accounts T1053.005 — Scheduled Task T1071.001 — Web Protocols (C2)

The slow-spray technique (T1110.003) is specifically designed to stay under volume-based detection thresholds. Correlating success events (EventID 4624) against recent failures on the same account — regardless of attempt count — would have surfaced this within minutes of the successful login.

05 Containment & Outcome

On confirmation of domain admin access and active C2 beaconing, immediate actions were taken: network isolation of the jump server and dc-backup-01, credential reset for j.harris and svc_deploy, and removal of the scheduled task. The C2 domain was blocked at the perimeter firewall.

The attacker had not exfiltrated data at the time of containment — the C2 traffic showed outbound beaconing but no significant data transfer volume in the 4-hour window. Post-incident forensics confirmed no data exfiltration.

Remediation recommendations delivered:

  • SIEM rule update: correlate 4624 success against any 4625 failures for same account/IP in prior 30 minutes regardless of count
  • Enable Credential Guard on all jump servers to block LSASS memory reads
  • Enforce MFA on all service accounts with cross-system access
  • Audit service account privilege scope — svc_deploy needed access to 3 systems, not 14
  • Disable NTLM authentication where Kerberos is available

Summary

Attack contained before data exfiltration. 5 remediation items implemented within 30 days. SIEM rule updated to catch success-after-failure regardless of threshold. Credential Guard deployed on jump server tier.
